# PHANTOM AI — mobile-first starter

Мобильное веб-приложение в чёрно-графитово-серебристом стиле: главный экран, чат, поиск, инструменты, профиль/настройки, меню и PWA-иконки. Интерфейс подписан моделью **TITAN.1.R**. Серверный адаптер подготовлен для API, совместимого с OpenAI Chat Completions. Реальная связь появится только после указания правильного адреса API и ключа.

## Почему на GitHub Pages дизайн может быть без стилей

HTML загружался, но ссылки на CSS/JS/иконки начинались с `/`, поэтому при открытии сайта из вложенного пути браузер искал файлы не там. В этой версии пути к интерфейсным ресурсам относительные (`./css/...`, `./js/...`) и работают при публикации `public` как корня сайта либо при открытии вложенного `public/index.html`.

**GitHub Pages публикует только статические файлы — Node.js `server.js` там не запускается.** Поэтому GitHub Pages годится для просмотра интерфейса, но для ответов модели приложение нужно открыть по адресу сервиса Render, где работает сервер. Чтобы GitHub Pages публиковал интерфейс без перемещения папок, включи в настройках репозитория Pages source **GitHub Actions**: добавлен workflow `.github/workflows/deploy-pages.yml`, который публикует `public/`.

## Структура репозитория — загружать из корня ZIP

```text
phantom-ai/
├── server.js
├── package.json
├── render.yaml
├── .env.example
├── README.md
├── public/                 # интерфейс сайта
│   ├── index.html
│   ├── css/style.css
│   ├── js/app.js
│   ├── manifest.json
│   ├── sw.js
│   └── assets/icons/
├── tests/
└── .github/workflows/
```

Не вкладывай всю папку `phantom-ai` внутрь второй папки `phantom-ai`: `package.json` и `server.js` должны оказаться в корне GitHub-репозитория. Папку `public` вместе с её подпапками не разбирай на отдельные плоские файлы — структура нужна для Render. Не загружай файл `.env` с секретами.

## Запуск

Требуется Node.js 20+.

```bash
npm install
npm run check
npm test
npm start
```

Открой `http://localhost:3000`. Без настроек ИИ сервер возвращает понятное сообщение, а не поддельный ответ.

## Render

Создай **Web Service** из репозитория и используй `npm install` как Build Command и `npm start` как Start Command. Можно также применить `render.yaml` Blueprint. В Render → Environment добавь:

- `TITAN_API_BASE_URL` — базовый URL API твоего провайдера, совместимого с OpenAI Chat Completions (обычно заканчивается на `/v1`, без `/chat/completions`).
- `TITAN_API_KEY` — настоящий ключ провайдера. Храни его только на сервере.
- `TITAN_MODEL` — `titan.1.R`.

Точное название модели задано как `titan.1.R`, но сам по себе model ID не определяет поставщика или URL. Убедись, что твой API поддерживает формат OpenAI Chat Completions; если у TITAN.1.R другой формат API, адаптер необходимо будет поменять под документацию провайдера.

Проверь `https://ТВОЙ-СЕРВИС.onrender.com/api/health`. Endpoint показывает `aiConfigured: true` только когда заданы и URL, и ключ; это не доказывает, что провайдер принимает модель, поэтому отправь тестовое сообщение в чат.

## iPhone PWA

После публикации по HTTPS открой **адрес Render** в Safari → Поделиться → На экран «Домой». PWA-файлы находятся в `public/`.

## Текущие ограничения

- Настроен интерфейс и серверная прокладка для OpenAI-compatible API. Подключение модели не считается проверенным, пока не внесены реальные `TITAN_API_BASE_URL` и `TITAN_API_KEY` и не прошёл пробный запрос.
- Живой поиск по интернету, Firebase, аккаунты, сохранение истории между устройствами и загрузка файлов пока не реализованы.
- GitHub-репозиторий/Render-сервис нужно создать в своих аккаунтах. Этот ZIP не публикует их автоматически.
